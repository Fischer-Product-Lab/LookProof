# Renderer compatibility

LookProof applies one provider-neutral Look to separate inert renderer bindings. It does not call those renderers. The same local policy and refusal semantics were exercised first, then each listed compiled condition was run as a separate bounded renderer test and reviewed independently.

| Renderer route | Ordinary request | Exact registration lock | Reference input | Independent pixel review |

The rows record compatibility with the tested request. They do not imply identical provider behavior, equal quality, or broad provider integration.

## xAI reviewed example

![Reviewed signal lantern from the Grok Imagine Image 2.0 compiled condition](assets/signal-lantern-grok-pass.png)

The ordinary lock required one navy hexagonal lantern, one cyan lens, one amber arch handle, exactly two coral block feet, one teal circular knob, a warm cream field, and no readable text.

The xAI route accepted one reference with `1K` and `1:1` settings. That combination returned a native 1024 by 1024 PNG. An independent blind review returned **PASS** for the complete ordinary identity lock. The reviewer counted one lantern, one lens, one handle, two feet, and one knob. The review found no text, watermark, duplicate part, clipping, inner frame, or material identity drift.

The route exposed a seed field, but the provider describes its image results as nondeterministic. Recording the seed provides a best-effort rerun input and does not establish reproducibility.

## Why GPT Image 2 is absent

OpenAI GPT Image 2 was not run. Its live route supported one reference and exact square output, and the local LookProof compile and refusal checks passed. The available cost result was not a token-inclusive estimate, so the paid visual test stopped before upload or dispatch.

A configured route is not enough. LookProof treats an unresolved cost boundary as a reason to stop, not as permission to guess.

## What this proves

- One provider-neutral Look compiled through separate Google, Black Forest Labs, and xAI bindings.
- The exact registration lock remained refused for every binding before renderer dispatch.
- Each listed renderer produced one independently reviewed ordinary identity pass in its bounded study.
- The xAI `1K` square setting produced an exact native square in this test.

This is not a benchmark. It does not establish model compliance, reproducibility, ranking, or that LookProof caused the pixels. The images remain reviewed examples, not keepers, authority, or production assets.
